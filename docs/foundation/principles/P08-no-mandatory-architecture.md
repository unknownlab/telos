# P08 — No Mandatory Application Architecture

## Definition

Telos does not require an application to use a specific architecture such as layers, hexagonal ports, a particular folder layout or a dependency-injection container. A project describes its own structure as Loci, containment and relations. The kernel checks that description for structural consistency and does not decide what the structure should be.

## Motivation

A framework that mandates an architecture makes every project look the same and makes the framework's own choices the project's problems. Describing the structure a project already has lets the framework help without taking the design decisions away from the team.

## In practice

- Containment in `packages/kernel/src/model.ts` records ownership between Loci for any layout; the kernel does not read folder names as meaning.
- The calculator in `apps/calculator` uses a plain structure of packages and modules, and its Loci are declared over that structure.
- No template or scaffold generated by Telos fixes a layout for user projects.

## Limits

- Describing an architecture is still a choice. A poor description gives poor checks.
- Some Archetypes will expect a structure. Those Archetypes say so in their own rules.

# Implementation Plan: Bun Monorepo Toolchain

**Branch**: `feat/bun-monorepo-toolchain` | **Date**: 2026-10-21 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `kitty-specs/bun-monorepo-toolchain-01M5E4T4/spec.md`

## Summary

Turn the repository root into a Bun workspaces monorepo skeleton (`apps/*`, `packages/*`, no packages yet) whose only tool is Bun canary `>=1.4.4-canary.1`: `bun check` for strict TypeScript, `bun lint` and `bun fmt` configured in `bunfig.toml`, and `bun test --pass-with-no-tests`. A small, real version-guard script enforces the minimum Bun version (Bun does not enforce `engines.bun`) and gives the checks a real input. A `pre-commit` hook in `.githooks/` formats and restages staged files, then blocks on lint, typecheck, test and `grace lint` failures. Spec Kitty's `review.test_command` runs the same suite read-only and blocks on regression. GRACE is initialised for the workspace layout. All behaviors below were prototyped in a scratch repo on Bun `1.4.4-canary.1` (see [research.md](research.md)).

### Command surface

| Script | Command | Mode |
|--------|---------|------|
| `preinstall` | `$npm_execpath scripts/check-bun-version.ts` | guard (runs with the invoking Bun) |
| `check:bun` | `bun scripts/check-bun-version.ts` | guard |
| `typecheck` | `bun check` | read-only |
| `lint` | `bun lint` | read-only |
| `format` | `bun fmt` | writes |
| `format:check` | `bun fmt --check` | read-only |
| `test` | `bun test --pass-with-no-tests` | read-only |
| `grace:lint` | `grace lint --path . --assertions current` | read-only |
| `verify` | `check:bun`, `format:check`, `lint`, `typecheck`, `test`, `grace:lint` in sequence, stop on first failure | read-only |

Scripts that share a name with a built-in (`lint`, `test`) are invoked as `bun run <name>`; the built-ins themselves use `--no-script` where needed to avoid recursion.

## Implementation Concern Map

### IC-01 — Workspace skeleton and TypeScript base

- **Purpose**: Root manifest, workspaces, strict shared tsconfig with project references, `@types/bun`, lockfile, `node_modules/` ignored.
- **Relevant requirements**: FR-001, FR-002, FR-003, FR-006, NFR-001, C-001, C-002
- **Affected surfaces**: `package.json`, `bun.lock`, `tsconfig.base.json`, `tsconfig.json`, `apps/`, `packages/`, `.gitignore`
- **Sequencing/depends-on**: none
- **Risks**: An empty `files` list fails `bun check` (TS18002); root tsconfig must include `scripts/`.

### IC-02 — Version guard, lint and format configuration

- **Purpose**: Enforce `>=1.4.4-canary.1` with a guard that compares via `Bun.semver.order`; configure `bun lint` / `bun fmt` in `bunfig.toml`; define the script surface including `verify`.
- **Relevant requirements**: FR-004, FR-005, FR-007, NFR-001
- **Affected surfaces**: `scripts/check-bun-version.ts`, `bunfig.toml`, `package.json` scripts
- **Sequencing/depends-on**: IC-01
- **Risks**: `Bun.semver.satisfies` rejects later-tuple prereleases (`1.4.5-canary.1`), so `order` is required; the guard must run with `$npm_execpath`, not `bun` on PATH.

### IC-03 — Pre-commit hook

- **Purpose**: POSIX `sh` hook: guard, `bun fmt --staged` (restages), `bun lint --staged`, `bun check`, `bun test --pass-with-no-tests`, `grace lint`; clear messages when Bun or `grace` is missing.
- **Relevant requirements**: FR-008, NFR-002, C-003
- **Affected surfaces**: `.githooks/pre-commit`
- **Sequencing/depends-on**: IC-02, IC-05 (needs `.grace/` for `grace lint`)
- **Risks**: Spec Kitty's own commits on mission branches pass through the hook; partially staged files are reformatted as a whole by `--staged` (document it).

### IC-04 — Review gate wiring

- **Purpose**: `review.test_command: "bun run verify && bun test --pass-with-no-tests --reporter=junit --reporter-outfile={output_file}"`, `review.fail_on_pre_review_regression: true`.
- **Relevant requirements**: FR-009, NFR-003, C-004
- **Affected surfaces**: `.kittify/config.yaml` (`review:` only)
- **Sequencing/depends-on**: IC-02, IC-05
- **Risks**: The gate parses JUnit; a non-test failure (lint, typecheck) produces no JUnit file. Implementation must confirm the gate blocks in that case and, if not, make `verify` failures visible through the gate's `FAIL <name>` text convention.

### IC-05 — GRACE initialisation

- **Purpose**: Run `grace-init` to create `.grace/` describing the workspace skeleton (root tooling, `apps/`, `packages/` areas) and pass `grace lint --path . --assertions current`.
- **Relevant requirements**: FR-010
- **Affected surfaces**: `.grace/`
- **Sequencing/depends-on**: IC-01
- **Risks**: Keep `.grace/` minimal and truthful; no modules that do not exist.

### IC-06 — Tooling documentation

- **Purpose**: Update `docs/tooling.md`: Bun canary requirement and upgrade, command table, hook behavior, review gate, GRACE status, remove "no toolchain yet" statements.
- **Relevant requirements**: FR-011
- **Affected surfaces**: `docs/tooling.md`
- **Sequencing/depends-on**: IC-01..IC-05
- **Risks**: `AGENTS.md` still says "No app toolchain exists yet"; it is a governance file, so the mission flags it for a separate owner-approved edit instead of changing it.
